# Project Knowledge

This repo has a pre-built knowledge graph generated by [Graphify](https://github.com/safishamsi/graphify).

- **Obsidian vault** (human-browsable): `~/vault/civic-ai/`
- **Graph JSON** (machine-queryable): `./graphify-out/graph.json`
- **Headline report** (start here): `./graphify-out/GRAPH_REPORT.md` if present, otherwise query the graph

Before reading individual source files, check the knowledge graph to understand
structure and connections. The graph is faster and uses far fewer tokens than
re-reading files.

## Vault layout (~/vault/civic-ai/)

- `architecture/` — human-curated architecture notes; populate as you make
  architectural decisions. Empty by default.
- `logs/` — session logs; after significant work, drop a dated note
  summarizing what changed. Empty by default.
- everything else at the vault root — auto-generated by `graphify export
  obsidian`. Includes one note per significant node in the graph (functions,
  components, classes, doc sections) plus per-case umbrella notes (e.g.
  `Case A CLC Workflow Automation.md`, `Case B Music Studio Infrastructure.md`,
  `Case C DEI Interactive Timeline.md`).

## When working in this repo

1. Start by querying the graph or scanning the vault for relevant context
2. Only read source files when the graph doesn't have what you need
3. After significant work, add a session log to `~/vault/civic-ai/logs/`
4. If you make architectural changes, update or add a note in `~/vault/civic-ai/architecture/`

## Querying the graph

Run from anywhere inside the repo (graph path defaults to
`./graphify-out/graph.json`):

```bash
graphify query "what connects the canvas API to the FastAPI processor?"
graphify path "Case B Music Studio Infrastructure" "RecapEditorModal"
graphify explain "AppLayout"
```

## Refreshing the graph

After **code-only changes** (cheap, local, no LLM):

```bash
cd /Users/caydenauyang/Code/Civic-AI-Github-Repository
graphify update .
graphify export obsidian --dir ~/vault/civic-ai
```

After **markdown / doc changes** (uses Gemini, costs cents):

```bash
cd /Users/caydenauyang/Code/Civic-AI-Github-Repository
source ~/.secrets   # loads GEMINI_API_KEY
graphify extract . --backend gemini
graphify export obsidian --dir ~/vault/civic-ai
```

The `.graphifyignore` at the repo root excludes binary image files from
extraction — re-add them by deleting matching lines if you want Gemini Vision
to caption portraits etc. (≈ $0.005/image).

## Per-case branching

This repo holds four cases under `projects/`. Per the team's convention, each
case has its own branch prefix (`case-a/`, `case-b/`, `case-c/`, `case-d/`)
and cases never share a branch. Tooling like this CLAUDE.md is the exception
— it lives on `main`. When working on case content, switch to the relevant
case branch before editing.
